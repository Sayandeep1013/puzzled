## Where we stopped, mid-task

**We had just stood up a development build + Metro loop, and it works.** That was
the fix for the real problem: I had rewritten the tray three times and the piece
depth twice *without ever seeing or touching the result*, because each attempt

The dev loop was proven working — Metro reported

phone rendered uncommitted working-tree code.

Immediately after that, I tried to drive the app's UI with `adb shell input tap`
to reach the board, and **it escaped the app into the user's personal screens
twice** (the dialer earlier, quick settings here). Those captures were deleted.

**Do not drive the UI with blind `adb input tap`.** Coordinates read off a
screenshot were still unreliable — taps appear to land before the UI settles.
Ask the user to navigate to the screen, then screenshot and analyse. Deep links
(`puzzled://…`) are safe and deterministic in a *release* build, but in a **dev
client they are swallowed by the dev launcher**, which is why navigation had to be
manual here.

## Resuming the dev loop

```sh
adb reverse tcp:8081 tcp:8081     # Metro over USB, no shared Wi-Fi needed
npx expo start --dev-client       # do NOT set CI=1 — it disables watch mode
```

Then launch the app. It loads from Metro, so **saving a file updates the phone in
about a second**. No build, no install, no EAS quota.

The dev-client APK is `ci-4` (330 MB) — already installed. Reinstall from
<https://github.com/Sayandeep1013/puzzled/releases/tag/ci-4> if needed.

Gotchas hit this session:

- `CI=1` silently disables watch mode. Metro prints
  `Metro is running in CI mode, reloads are disabled`.
- The dev client shows a floating dev-menu bubble and an opening dev-menu sheet;
  the sheet dims the screen and ruins screenshots. Dismiss it first.
- The phone dozes and locks. Screenshots come back solid black and
  `mWakefulness=Dozing` / `mDreamingLockscreen=true` in `dumpsys power` / `window`.
  Ask the user to unlock; do not try to get past the lock screen.

## Uncommitted work in the tree

`src/features/game/puzzle-board.tsx` only. Typecheck and lint pass; **not yet seen
running on the board**. Four changes:

1. **Corner rounding restricted to true corner pieces.** The previous version
   intersected *every* piece with a rounded rect of its bounds, rounding all four
   corners of all pieces, which opened visible notches at interior joints. Now only
   the four corner pieces round, and only their one outward corner, built with
   `arcToTangent` because a rounded rect cannot round one corner and leave three
   square.
2. **Cream mat around the board**, with the mat carrying the drop shadow — the
   treatment the mockup uses.
3. **Slider pill accented**: white, ringed in `colors.grass`, with three grip lines
   so it reads as draggable.
4. **Drop shadow removed from the dragged piece.** A blurred Skia filter
   re-rendering every frame under the finger is the most expensive thing on screen
   at exactly the moment latency is felt. This is a *hypothesis* about the reported
   lag — it has not been measured.

`.env.example`, `.prettierignore`, `.prettierrc.json` show as modified but are
line-ending churn only (`git diff --ignore-all-space` is empty). Ignore them.

`gameboard image screenshot.jpeg` (repo root) is the user's own screenshot of the
board — the most useful single artefact in this session. `puzzle assets/` is the
team's original delivery, untracked on purpose; normalised copies live in

## What the mockup actually specifies

Verified by cropping `puzzle assets/inspiration image.png` at 8–10x. Crops are
reproducible with `System.Drawing` — see the session transcript, or re-crop panel 2
(x 236–470, y 8–422).

- **The board is a framed picture.** A cream mat about 10pt wide with its own
  rounded corners; the *mat* casts the drop shadow, not the artwork.
- **Depth is shadow, never light.** There is no light rim anywhere in the mockup.
  Pieces cast a soft shadow down and slightly right and carry a thin *darker* edge.
  An earlier attempt rimmed pieces in near-white; it reads as glow, not as a tile.
- **Locked and unplaced pieces are treated differently.** Tray, loose and lifted
  pieces are objects above a surface and cast shadows. Locked pieces belong to the
  finished picture and show only thin dark seams — embossing them makes the
  assembled image look tiled. `PieceFill` takes a `raised` flag for this.
- **Corner rounding follows the board frame.** The corner piece's outward corner is
  round; interior joints stay sharp.
- Locked pieces do have a *tight* shadow either side of each seam — slightly more
  than the current hairline. Not yet implemented.

## Build and release setup

**GitHub Actions replaced EAS.** `.github/workflows/android-apk.yml`. The repo is
public, so Actions minutes are effectively unlimited; the EAS free tier allowed
only a handful of Android builds a month and four were spent in one day.

- Triggers on push to `main` and `design/**`, plus manual dispatch with a
  `release`/`debug` choice.
- **`release` is the default and must stay that way.** `assembleDebug` produces a
  development build: no embedded JS bundle and expo-dev-client's launcher instead
  of the app, so it only runs while Metro is reachable. `ci-2` was such a build and
  could not start; it was deleted. Note `inputs.variant` is empty on a push
  trigger, so the *fallback* in the Gradle step decides — it must be Release.
- Cheap gates (typecheck, lint, tests) run before Gradle.
- Each build is published as a **prerelease** tagged `ci-<run_number>`. Actions
  *artifacts* need authentication even on a public repo; release assets are plain
  anonymous HTTPS, so a build can be pulled with `curl` and pushed to a device.

Release signing is **deferred** — builds are debug-signed, so every install needs
`adb uninstall com.puzzled.app` first, which wipes saved progress.
`docs/android-release-signing.md` has the full procedure. The keystore must go from
`eas credentials` straight into GitHub Secrets and **must not pass through a chat
transcript**; the repo is public, so a leak there is immediate compromise.

Releases: `ci-3` is the last working standalone build, `ci-4` is the dev client.

**API rate limits:** anonymous GitHub API is 60 requests/hour and polling
exhausted it once. Authenticated is 5,000. There is no `gh` CLI and no token on
this machine; Git Credential Manager holds a credential for `github.com` that can
be read with `git credential fill` — used this session to delete the `ci-2`
release. Never print it.

## Process lessons worth keeping

1. **Do not iterate on gesture or feel through CI builds.** Use the dev loop.
2. **Measure performance, never assert it.** `dumpsys gfxinfo`.
3. **Grep for raw values, not just token names.** The orange that survived three
   removal attempts was a hardcoded `rgba(232,110,69,0.95)` on `FloatingPiece`; every
   sweep searched for `colors.apricot` and could not see it.
4. **Clear logcat before checking it.** `logcat -d` dumps the whole buffer; stale
   entries from a previous run nearly caused a false "still broken" report.
5. **Verify a diagnosis before fixing it.** Two reported problems were not real: the
   Results screen's blank time was adb eating `&` in a deep link, and Library
   already defaulted to In Progress.
