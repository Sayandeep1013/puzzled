# Signing the GitHub Actions APK with the real key

**Status: not done. The workflow currently produces a debug-signed APK.**

This is a deferred task, kept here so it can be picked up cold. Until it is done,
every install needs the previous build uninstalled first:

```sh
adb uninstall com.puzzled.app
adb install <downloaded>.apk
```

That is acceptable during development. Do this task when you want installs to
upgrade in place — i.e. when you start caring about keeping saved progress between
builds, or when you approach a Play Store submission.

---

## Why it matters

Android refuses to upgrade an app if the new APK is signed with a different key.
The debug key the workflow uses now is not the key EAS used for the builds already
on your phone, which is why installs need an uninstall first — and an uninstall
wipes the app's SQLite data: progress, coins, hints, settings.

Signing Actions builds with the *same* key EAS uses makes those installs
upgrade-compatible with each other and with anything already on the device.

## What is needed

Four values. Three are secrets.

| Secret | What it is |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the `.jks` keystore, base64-encoded |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_PASSWORD` | key password (often the same as above) |
| `ANDROID_KEY_ALIAS` | key alias — not secret, but store it alongside |

## Getting them out of EAS

The keystore lives on Expo's servers. Fetch it yourself:

```sh
npx eas-cli@latest credentials
```

Then choose **Android** → the **preview** (or production) profile → **Keystore**
→ **Download existing keystore**. It writes a `.jks` file and prints the alias and
both passwords.

`eas credentials` is interactive and deals in a private signing key, so run it
yourself rather than having an assistant run it.

## Loading them into GitHub

Encode the keystore:

```sh
# macOS/Linux
base64 -i ./your-keystore.jks | tr -d '\n' | pbcopy

# Windows PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("./your-keystore.jks")) | Set-Clipboard
```

Add all four at **GitHub → repo → Settings → Secrets and variables → Actions →
New repository secret**.

> **Paste these into GitHub directly. Do not paste them into a chat, a commit, an
> issue, or a file in the repo.** A signing key plus its passwords is enough for
> someone to publish an app that Android will accept as yours. GitHub Secrets are
> encrypted and masked in logs; a chat transcript is neither. Anyone helping with
> this task should be told the secrets are set, not what they are.

Delete the local `.jks` once it is uploaded, and keep a copy somewhere safe
offline — losing it means you can never update a published app under that key.

## Then change the workflow

In `.github/workflows/android-apk.yml`, before **Assemble APK**:

```yaml
      - name: Restore keystore
        env:
          KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
        run: echo "$KEYSTORE_BASE64" | base64 -d > android/app/upload.jks

      - name: Configure signing
        env:
          STORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
          KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
          KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
        run: |
          cat >> android/gradle.properties <<EOF
          PUZZLED_UPLOAD_STORE_FILE=upload.jks
          PUZZLED_UPLOAD_STORE_PASSWORD=$STORE_PASSWORD
          PUZZLED_UPLOAD_KEY_ALIAS=$KEY_ALIAS
          PUZZLED_UPLOAD_KEY_PASSWORD=$KEY_PASSWORD
          EOF
```

Then switch the default variant to `release`, and teach Gradle to use it. Because
`android/` is generated by `expo prebuild` and gitignored, editing
`android/app/build.gradle` directly will not survive — it needs an Expo **config
plugin** that injects the `signingConfigs` block during prebuild. Put it in
`plugins/withReleaseSigning.js` and register it in `app.json`.

## Verifying

```sh
# Should print the same SHA-256 as the EAS-built APK
keytool -printcert -jarfile <downloaded>.apk
```

If the fingerprints match, `adb install -r` will upgrade in place and the app's
saved data survives.
